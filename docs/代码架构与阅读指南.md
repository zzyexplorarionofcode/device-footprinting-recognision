> 目标读者：第一次打开这个包、想在一两天内看懂「方法怎么变流量、实验怎么跑、数字怎么来」的人。

## 0. 一句话概括

这是一个 **IoT 设备指纹识别防御** 的完整可复现实验包：把 PCAP 抓包切成固定长度的双向流，
用一套「随机弱化 + 类别诱导码 + 位置锚点 + 映射轮换 + 零和抖动」的流量变换（FADE / 内部名 Method33）
改写流，再训练 MLP/RF/SVM/LSTM 攻击者去识别设备，测量在不同「攻击者重训练比例」下的识别率与物理开销；
同时附带 6 个对照基线（Random Rate、Constant Rate、Traffic Morphing、IoTGAN、iPET、Glimpse）和 1 个独立基线（Securitas）。

方法的核心假设：**设备指纹主要来自包长/方向/间隔的时序模式**。FADE 不加密、不改协议，只改可观测的
「包长、gap、新增包」三类事件，并且用严格的逐流物理预算（630 B / 1.5 s / 6 个新增事件）约束改造强度。

## 4. 必须先记住的三份「数据契约」

### 4.1 流表示：`[N, 32]` 四数组

| 数组 | 含义 | dtype |
| --- | --- | --- |
| `lengths` | Ethernet 帧长（byte），新增 dummy 也在这里 | float32/64 |
| `gaps` | 与同流前一事件的时间差（秒），首包恒为 0 | float32/64 |
| `directions` | 设备发出 `+1`，设备收到 `-1` | int8 |
| `mask` | 有效事件 1；右侧 padding 0 | int8 |

约束：mask 必须是**左对齐前缀**（不能出现 `0→1`）；有效包长度为正、gap 非负；
`labels` 是一维 `[N]` 且必须从 0 连续编号；`groups` 是「设备/capture」标识，**切分以它为单位**。

### 4.2 防御输出：七元组协议

```
(lengths, gaps, directions, mask, stats, metadata, audit_rows)
       前四项：变换后的固定窗口  第五项：逐流成本  第六项：批次元数据  第七项：逐流审计
```

- 所有方法（FADE 和 6 个基线）都返回这七项，`validate_application` 统一校验前四项形状。
- `stats` 的字段名由 `STAT_KEYS` 约定（`method33.py:227`，`baselines/common.py:20`）：
  `real_added_bytes/delay`、`dummy_count/bytes/delay`、`retained_dummy_count`、
  `displaced_real_packets`、以及 inbound/outbound 拆分。
- 时间指标由 `TIMING_KEYS` 统一：`real_completion_delay_seconds`（最后**真实**包被推迟多久）、
  `wire_completion_delay_seconds`（最后**发送事件**被推迟多久）、`cover_tail_seconds`（尾部覆盖时长）。

> 关键概念区分：**完整事件序列 ≠ 分类器看到的前 32 个事件**。
> 插 dummy 不会删除网络上的真实包，只会把队尾真实包挤出观察窗口；
> `_render_fixed_window` 同时记录 `complete_*` 与 `retained_*`，审计里
> `displaced_real_packets` 统计的就是这种「窗口位移」，不是丢包。

### 4.3 特征：64 维（2L）

`pcap.make_features`（`data_pipeline/pcap.py:1141`）：
前 32 维 `direction * length / 1514`（带符号归一化长度），后 32 维 `log1p(min(gap,10s) * 1000)`
（毫秒后取 log1p）。第一列 gap 强制为 0，因为观察者没有首包前的共享时钟。

## 6. 核心算法拆解（FADE / Method33）

### 6.1 三层预算

| 层 | 预算 | 内容 |
| --- | --- | --- |
| hard（总） | 630 B / 1.5 s / 6 事件 | 单流新增上限 |
| weakener | 347 B / 1.05 s / 3 dummy | 随机 padding/delay + 弱化 dummy |
| trigger | 283 B / 0.45 s / 2 dummy | 每个码字恰好两包，字节与 gap 之和等于分账 |

`Budget` 是「字节、时延、dummy 数」三元组；`validate_config` 会检查两个子预算之和不超过 hard。
配置里弱化器固定发 3 个 dummy、诱导码固定 2 个，合计 5 个新增事件（上限 6 留有余量），
最小 gap 为 4 ms。

### 6.2 弱化器（label-free）

- 只作用于**真实上行包**：以 `padding_probability` 决定是否 padding、`delay_probability` 决定是否 delay，
  两次独立抽样，可以同时发生。
- 实际 padding = `min(目标长度-当前长度, 单包上限, 剩余分账, MTU 余量)`，**只会变长**；
  delay 同理，只会变晚。
- 弱化 dummy 的插入位置是「第几个上行真实包」（slot），不是数组列号；计划在流开始时一次抽完，
  再按 `outbound_ordinal` 单调消费。**弱化器全程不读 label**——这是论文的可证明性质，
  审计字段 `random_weakener_used_label: false` 就是在记录它。

### 6.3 诱导码与位置锚点

- `trigger_codes[class] = ((len1,gap1),(len2,gap2))`：每个类别一个两包码字，**所有类别等成本**。
- `old_mapping` / `next_mapping` 把「可信设备标签」映射到「码字下标」；`next` 必须是无固定点的错排，
  这样轮换后同一设备换用另一个码字。
- 位置不是固定列，而是 `trigger_positions[code] = (a, b)`：在**原始真实包**（双向都计数）的第 a、b 个之后插入。
  配置可显式给出位置表（本包的 `fade_cic_active.json` 是 10 对、`fade_unsw8.json` 是 8 对），
  没有配置时退回 `default_trigger_positions`（取 1/4/8/12/16 两两配对，先距离 2 的边、再距离 1 的边）。
  位置由码字下标决定，因此**改 label 会同时改码字与位置**，但不会改变随机流。
- 短流到不了锚点：流结束后把剩余 trigger dummy 追加到尾部，并在 audit 里写
  `trigger_short_flow_fallback_used`。这仍然只依赖过去（流已结束），不偷看未来。

### 6.4 零和抖动（`jitter_trigger_code`）

目的：让同一个码字每次部署都不完全一样，同时**一字节、一毫秒都不多花**。

1. 先算「可行转移量」区间：把 `+δ` 从第二包转给第一包（长度整数、gap 连续），
   同时满足 ±5% 相对界、最小以太网帧长、最大帧长、最小 gap。
2. `length_uniform_quantile` / `gap_uniform_quantile` 由 `SeedSequence([seed, flow, 32, 5_000_000])`
   独立抽取，**不含 label、不含 mapping**；old/next 配对实验因此能用公共随机数。
3. 第二包 = `预算 - 第一包`（而不是独立算 `second-δ`），把所有浮点残差固定收在一处；
   再用 `np.nextafter(-inf)` 消掉最后 1 ULP 的越界，最后用 `rtol=0` 的断言复核。
4. 位置不参与抖动：`trigger_positions_changed_by_jitter: false`。

这套「先区间、后分位、最后断言」的写法是本文件最值得学的工程技巧：**随机化不能以放弃预算证明为代价**。

### 6.5 映射轮换（`rotation_history.next_distinct_mapping`）

- 约束：每个类别在新映射里必须拿到**历史上从未用过的码字**（不允许类别-码字对复用）。
- 目标：最大化与上一版映射的「码字距离」（`_trigger_feature` 把两包长度/gap 拼成向量取欧氏距离）。
- 实现：对 `(已用码字集合, 类别下标)` 做**位掩码 DP**；距离用 `float.as_integer_ratio()` 转成整数权重，
  避免浮点比较在最优解并列时抖动。`mapping_schedule` 从 old/next 出发，逐版扩展到 3 版。
- 轮换不是「随机换一个」：它同时保证**历史不可复用**与**距离尽量大**，是论文「持续攻击者」实验的基础。

## 7. 实验协议（数字是怎么来的）

### 7.1 划分

- 默认 `split.unit='capture'`：以完整 PCAP（或 UNSW 的 UTC 日）为单位切分，防止同源泄漏。
  `split_by_capture` 会断言训练/测试的 group 集合无交集。
- UNSW 主数据集使用**冻结分区**：先按 UTC 日 75/25 分 outer train/test，再在 75% 内 80/20 分 train/valid；
  只有训练侧按类别最多保留 10000 条。`frozen_partition` 会重新核对 manifest 中的日期、计数、上限，
  **不允许对已抽样的数据再随机切分**。

### 7.2 攻击者与重训练比例

- 模型：`MLP-full`、`RF-full`、`SVM-full`、`LSTM-full`；同一 `StandardScaler` 只在训练侧拟合。
- `retraining_ratio=r` 的精确定义：复制干净训练矩阵，**只把 mask 为 True 的行替换成同一批流的受保护版本**，
  样本数与标签不变；测试集**永远 100% 受保护**。
- `build_stratified_nested_masks` 每类只打乱一次，比例越大取越长前缀 → 10% 的样本严格包含在 25% 里，
  曲线变化来自比例而不是「换了一批样本」。

### 7.3 种子体系

一次观测的种子由 `apply_seed + repeat*seed_step + adapter.seed_offset (+ 1000*model_slot)` 组合，
train/test 再差 `test_apply_seed_offset`。设计意图：
- 每条流用 `SeedSequence([seed, flow])` 隔离，**改一条流不会让后面的流随机性错位**；
- 方法顺序变化不影响任何方法的种子（seed_offset 写在配置里，不靠列表下标）；
- train/test 用不同种子，防止攻击者「记住」测试流的同一次随机实现。

### 7.4 产物

```
artifacts/runs/fade/<case>/<时间戳>/
├── observations.csv          逐 (方法, repeat, 比例, 模型) 的最细粒度结果
├── per_model_summary.csv     方法×比例×模型的均值/标准差
├── ratio_summary.csv         跨模型总体 + strongest_attacker
├── overhead_summary.csv      测试流开销均值/p95/max
├── overhead_by_target.csv    按 IoTGAN 目标模型拆分的开销
├── budget_audit.csv           逐 split 的预算命中率与最大值
├── split_indices.npz          冻结的 train/test/validation 行号
├── manifest.json              配置快照、数据/源码 SHA-256、软件版本、协议说明
└── checkpoints/               策略、攻击者、每步结果的可复用检查点 + index.json
```

`manifest.json` 存在 = 该 case 完整结束（先写 CSV 并算摘要，最后原子写 manifest）。
恢复用 `--resume RUN_DIR`，`checkpoint_contract` 会比对配置、数据、源码与软件版本，
不一致就拒绝复用——**不能把别的实验权重混进来**。

## 8. 复杂语法 / 工程模式速查

| 语法或模式 | 出现位置 | 为什么这么写 |
| --- | --- | --- |
| `@dataclass(frozen=True)` | 几乎所有配置类 | 运行中不可变，避免长实验中途被改预算/映射 |
| `TypeAlias` 七元组 | `method33.py:210` | 只是可读性标注，运行时不复制数据 |
| `zip(..., strict=True)` | `_sample_dummy_plan`、`split_by_capture` | 长度不齐时立刻报错，而不是静默截断 |
| `np.random.SeedSequence([seed, flow])` | 每流 RNG | 流间随机流隔离，可复现且互不干扰 |
| `mask.astype(bool)` + 回比较 | `_coerce_inputs`、`validate_dataset` | 用「转 bool 再转回是否相等」拒绝 0/2 之类非二值 mask |
| `np.flatnonzero(mask[sample])` | 在线遍历 | 只遍历有效前缀，`source_index` 与真实事件顺序一一对应 |
| `while ... < len(code) and slots[i] == ordinal` | 插 trigger/dummy | 用单调指针消费有序计划，O(n) 而非每包搜索 |
| 位掩码 DP `used | bit` | `next_distinct_mapping` | 状态 = 已用码字集合，类别数 ≤ 10 时规模极小 |
| `float.as_integer_ratio()` | 轮换距离权重 | 把浮点距离转成整数权重，最优解比较无舍入歧义 |
| `np.nextafter(x, -inf)` | jitter 收尾 | 只下调 1 ULP，把「容差内不超」加强为「真的不超」 |
| `@contextmanager` + 文件锁 | `run_guard`、`_cpu_threads` | 目录互斥/线程数恢复，异常路径也能释放 |
| `ClassifierMixin, BaseEstimator` | `LSTMAttacker` | 继承 sklearn 协议，可进 `joblib`、可被统一评测循环调用 |
| `torch.random.fork_rng(devices=[])` | LSTM 训练 | 只种子化 CPU 生成器，不污染 CUDA 全局状态 |
| `__getstate__/__setstate__` | LSTM 持久化 | 保存前把权重搬到 CPU，避免 CPU 机器反序列化 CUDA 张量失败 |
| `utf-8-sig` | `write_csv`、配置读取 | 兼容 Windows Excel 与带 BOM 的 JSON |
| `atomic_json` / `os.replace` | 所有结果落盘 | 崩溃时不会留下半个 JSON；manifest 最后写 |

## 9. 常见坑

1. **别把「观察窗口」当成「网络事件」**：`displaced_real_packets` 不为 0 是正常的窗口位移。
2. **别对已冻结的 UNSW 数据再切分**：`frozen_partition` 会直接报错，重切会破坏 1 万/类上限的语义。
3. **别用 `--limit-captures` 的结果当正式数据**：那是诊断样本，文件名和 manifest 都会标 `_sample`。
4. **`glimpse` 需要单独的 TensorFlow 环境**，与 PyTorch 的 `typing-extensions` 版本冲突；
   只学 FADE/其他基线时把 `configs/experiments/common.py` 里对应条目 `enabled=False`。
5. **旧 NPZ 没有 `data_protocol`** 会被 `prepare_context` 拒绝；这是有意的，避免协议混淆。
6. **Method33 配置与数据集设备顺序绑死**：`validate_dataset_project_alignment` 会核对类别数与设备名。
