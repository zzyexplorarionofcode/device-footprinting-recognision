# 数据处理与运行说明

以下命令均从学习包根目录执行。原始数据需自行准备；示例中的盘符路径改为自己的数据目录。输出默认位于本包的 `data/processed/` 和 `artifacts/`。

## CIC 数据

准备 CIC-IoT-2022，根目录应含 `Device List.xlsx`、`active/`；需要 Idle 数据时另有 `2-Idle/`。设备选择和会话参数在 `data_pipeline/cic.py` 中。

```powershell
python -B -m data_pipeline.cic --root "F:/iot dataset/cic2022" --mode active
```

主评估使用生成的 `data/processed/cic_v2/flows_cic_active_10class.npz`。提取器按设备、TCP 连接及会话边界处理双向包，至少保留 4 包、每条会话最多编码 32 个原始包。按完整 PCAP 划分训练和测试，避免同一抓包泄漏。

处理器仍支持 `--mode idle`，但本包不包含 Idle 实验配置。`--limit-captures` 仅用于诊断，不应把部分数据当作正式数据集。

## UNSW 数据

主流程固定为 8 类：AugustDoorBell、iHome、NetatmoWelcome、AmazonEcho、WithingsSleepSensor、TribySpeaker、PhilipsHue、PixStarPhotoFrame。

```powershell
python -B -m scripts.audit_unsw_counts "F:/iot dataset/UNSW-IoTraffic" artifacts/preprocessing/unsw_counts --workers 3
python -B -m data_pipeline.unsw_main "F:/iot dataset/UNSW-IoTraffic" data/processed/unsw_main8_v1 --count-audit artifacts/preprocessing/unsw_counts/manifest.json --workers 3
```

第二步的输出目录必须尚不存在。先按全局 UTC 日期划分：75% 日期进入开发侧，其中 80% 为训练、20% 为验证，其余 25% 日期作为最终测试。只有训练部分按类别最多保留 10000 条，验证与测试保留对应日期的全部合格会话。计数审计、原始文件摘要及冻结划分会写入元数据；所有方法读取同一份划分。

主文件为 `data/processed/unsw_main8_v1/flows_unsw_8class.npz`。不要对生成的 NPZ 再做随机流级切分。

## FADE 单次轮换评估

```powershell
python -B -m experiments.run_experiment --case cic_active_session_v2 --dry-run
python -B -m experiments.run_experiment --case unsw_8class_main --dry-run
python -B -m experiments.run_experiment --case cic_active_session_v2
python -B -m experiments.run_experiment --case unsw_8class_main
```

默认配置为 `configs/experiments/current.py`。攻击者包括 MLP、RF、SVM 和 LSTM；训练使用所有训练行，类别权重仅依据训练集计算。重训练比例为 0、10%、25%、50%、75%、100%。

完整实验可能耗时较长。学习时可在配置副本中减少重复次数或 LSTM 轮数，并使用新的输出目录；这样产生的是学习运行。断点续跑使用运行器的 `--resume RUN_DIR`，它会核对配置、数据和源码，不能把别的实验权重混入。

## 独立应用 FADE

```powershell
python -B -m methods.method33_tools --config configs/methods/fade_unsw8.json inspect
python -B -m methods.method33_tools --config configs/methods/fade_unsw8.json apply --dataset data/processed/unsw_main8_v1/flows_unsw_8class.npz --output artifacts/fade_application.npz --mapping next --seed 731800 --trace
```

`inspect` 不读取真实数据；`apply` 的输入须与配置的设备顺序一致，输出路径必须是新文件。`--trace` 适合查看完整事件，处理大数据时会增加内存和输出体积。

python -B -m experiments.run_experiment --config configs/experiments/baselines.py --case cic_active_session_v2 --dry-run

## Securitas 独立流程

Securitas 在 `baselines/securitas/` 下独立训练与评估，配置为 `configs/cic_active.json` 和 `configs/unsw8.json`。它需要从原始 PCAP 恢复真实报头；原始数据位置改变后，用 `--capture-root` 指向对应抓包目录。

以 CIC Active 为例：

```powershell
python -B baselines/securitas/prepare_headers.py --config baselines/securitas/configs/cic_active.json --capture-root "F:/iot dataset/cic2022/active" --partition train-validation --output data/processed/cic_v2/securitas_active_train_headers.json
python -B baselines/securitas/prepare_headers.py --config baselines/securitas/configs/cic_active.json --capture-root "F:/iot dataset/cic2022/active" --partition test --output data/processed/cic_v2/securitas_active_test_headers.json
python -B baselines/securitas/run.py train --config baselines/securitas/configs/cic_active.json --output artifacts/runs/securitas/cic_active/training --headers data/processed/cic_v2/securitas_active_train_headers.json
python -B baselines/securitas/experiment_icmp.py --classes 10 --config baselines/securitas/configs/cic_active.json --output artifacts/runs/securitas/cic_active --test-headers data/processed/cic_v2/securitas_active_test_headers.json
python -B baselines/securitas/report_experiment_icmp.py --classes 10 --output artifacts/runs/securitas/cic_active
```

UNSW 同理，把配置改成 `unsw8.json`、`--classes` 改成 8，报头文件放在 `data/processed/unsw_main8_v1/`，并选新的输出目录。报头 sidecar 与数据集摘要绑定，不能随意换文件。

## 多次轮换

```powershell
python -B -m experiments.run_rotation --scenario new --case cic_active_session_v2 --dry-run
python -B -m experiments.run_rotation --scenario persistent --case unsw_8class_main --dry-run
python -B -m experiments.run_rotation --scenario new --case cic_active_session_v2
python -B -m experiments.run_rotation --scenario persistent --case unsw_8class_main
```

两种场景均进行三次映射轮换。新攻击者只用当前映射的数据训练；持续攻击者积累之前的历史。不要将这两个场景的结果含义混用。
