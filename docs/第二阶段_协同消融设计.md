# 第二阶段设计：诱导包与弱化包协同消融

> **状态（2026-11-02）：A.1/A.2、Position placebo、失败诊断/rotation dose、K 稳定性、时间序列 pilot、当前映射校准曲线已完成。**
> 结论：
> - Real ≈ Placebo code；核心是 **position mapping rotation**；
> - K=1 固定类位置最强；K=2/4/8 单调削弱，位移标准化后仍成立；position-only validation-aligned K=1..8 接近 1，说明位置信息仍在；
> - 时间序列 pilot：Fixed J=0.965、Periodic J=0.828、Per-flow J=0.897；
> - 校准曲线：n=0→1024 当前映射标签，traffic BA 仍 0.26–0.28，**标签不能恢复 traffic 性能**；与 position-only 可对齐形成对照，说明 rotation 同时破坏可迁移表示。
> 待做：K 熵控制、完整时间矩阵（滑窗/warm-start/相对阈值/censoring/多相位）、overlap。
> 详见各专项报告。

## 1. 需求评估

目标是改变 **trigger（诱导包）数量 T** 与 **weakener（弱化 dummy）数量 W**，分析二者对攻击者 BA、长度直方图与交互效应的影响。

这个方向值得做，但当前实现不是“配置里改两个整数”即可：

| 约束 | 现状 | 影响 |
| --- | --- | --- |
| trigger 包数 | `apply_method33` 要求恰好 2 个 trigger 包；`trigger_packet_count=2` 硬校验 | 只能做 T=0（关闭）或 T=2（现有），不能做 T=1/4 |
| trigger 位置 | 每个类只有一对位置（2 个 trigger） | 多对 trigger 需要新的位置表 |
| trigger jitter | 代码假设每个 flow 恰好 2 个 trigger 事件 | 多 trigger 需要重写 jitter/审计 |
| weakener 数量 | `weakener_dummy_count` 可配，但必须等于 weakener 预算的 `dummy_packets` | 可以改，但要同步预算/槽位校验 |
| 总预算 | weakener + trigger ≤ 630 B / 1.5 s / 6 dummies | 改数量必须重新分账，否则不是等成本 |

**结论：**

- **Stage A（可立即做）**：trigger 只做 on/off（T=0 或 2 包），weakener 做 0..5 的剂量扫描；位置固定为 v2 候选。这能回答“诱导包存在与否 × 弱化包剂量”的协同问题。
- **Stage B（需要 refactor）**：真正的多 trigger 包/多对 trigger（T=1/2 对/4 包等），需要改 `method33.py`、位置表、jitter 与审计；工作量和风险都显著更高。

## 2. 关键定义（必须先确认）

“诱导包数量”有三种可能定义，实验含义不同：

1. **T = trigger 事件数**：0、1、2 个包；当前只支持 0/2，1 需要改代码。
2. **T = trigger 对数/code 数**：每对 2 个包；T=0/1/2 对 → 0/2/4 个包；需要多对位置与 jitter。
3. **T = trigger codebook 的条目数**：与“对数”类似，但还涉及每类是否共享/独立 code。

建议 Stage A 用 **T ∈ {0, 2}（事件数）**；Stage B 若要剂量响应，用 **T ∈ {0, 1, 2 对}（0/2/4 包）**。

## 3. 等成本规则

每个 cell 必须满足：

- 总字节 = 630 B（L2 帧长口径）；
- 总新增时延 = 1.5 s；
- 总 dummy ≤ 6；
- trigger 与 weakener 的字节/时延按 cell 重新分账；
- 位置固定为 v2 position candidate，避免位置混淆。

同时增加一个 **固定事件数控制**：例如所有 cell 都保持 5 个 dummy，只改变 trigger/weakener 组成；这样可以把“组成效应”与“事件数/成本效应”分开。

## 4. Stage A 矩阵（建议先做）

| cell | trigger 包数 T | weakener 数 W | 总 dummy | 说明 |
| --- | ---: | ---: | ---: | --- |
| A0 | 0 | 0 | 0 | 无防御对照 |
| A1 | 0 | 3 | 3 | weakener-only |
| A2 | 0 | 5 | 5 | weakener-only 高剂量 |
| A3 | 2 | 0 | 2 | trigger-only |
| A4 | 2 | 1 | 3 | 低 weakener |
| A5 | 2 | 3 | 5 | 当前 FADE |
| A6 | 2 | 4 | 6 | 高 weakener（硬上限） |

可选扩展：T=0/W=1、2、4；T=2/W=2。每个 cell 在 UNSW-IoTraffic 与 CIC 上跑，LR/RF/MLP，clean/retrained，位置固定，5 个 seed（或至少 3 个日期折）。

## 5. 指标

每个 cell 记录：

- BA（clean / retrained，三模型）+ 配对 bootstrap CI；
- 逐类 recall；
- 真实包 padding 字节、dummy 字节、事件数；
- 按 role 的长度直方图（real / trigger / weakener / merged）；
- 直方图距离：real vs trigger、real vs weakener、merged vs clean；
- 机制分解：representation / displacement / dummy_mixing；
- trigger/weakener 的交互项：`BA(T,W) − BA(T,0) − BA(0,W) + BA(0,0)`。

## 6. 混淆因素

1. **T=0 同时移除了“事件数”和“类特定 code 信号”**；需要 placebo trigger（同数量、class-independent 随机长度）来分离。
2. **等成本但不等事件数**：T/W 改变会改变每事件平均字节；必须同时报告固定事件数控制。
3. **位置固定**：Stage A 固定 v2 position，不重新搜索，否则无法归因。
4. **预算分账**：trigger 字节随时长改变后，weakener 预算变化；要报告实际分账。
5. **窗口位移**：T/W 改变会改变真实包被挤出的数量；必须记录 `displaced_real_packets`。
6. **RNG**：v2 内容指纹保证重放，但不同 cell 的 dummy 计划不同；每个 cell 固定 seed 与同一批流。
