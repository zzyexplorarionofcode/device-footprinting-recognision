# 在线适应 10 天/block：Fixed / Periodic / Per-flow

## 1. 协议

- UNSW，10 天/block，16 个测试 block；
- 历史最多 3000 条，SGD log-loss；
- 当前 block 前 n 条标签，剩余盲测；
- n=0/64/256/1024；
- 方法：permutation / probe / finetune；
- Periodic 额外：schedule-known、state-inferred；
- 单 phase（phase=0），period=2。

## 4. 关键观察

1. **Fixed > Per_flow > Periodic**：
   - Fixed J≈0.70–0.84；
   - Per_flow J≈0.62–0.76；
   - Periodic J≈0.45–0.66；
   - Periodic 仍是最低。

2. **Mapping-aware 实现失败/不可解释**：
   - schedule-known J≈0.52–0.60，低于 unaware 0.64–0.66；
   - state-inferred 在 n≥64 时反而降到 0.45–0.55；
   - 这不是“mapping-aware 无用”，而是当前实现有数据/选择问题：
     * 每个状态的 expert 只分到 1/6 历史数据；
     * prefix 标签可能集中在少数类/早期 flow；
     * state 打分用 prefix 准确率，噪声大。
   - 因此**不能据此判断 Periodic 优势是否真实**。

3. **Prefix 标签有偏**：
   - probe 在 n=64/1024 经常伤害 BA；
   - 第一个 block 的 prefix 可能来自少数类/特定日期；
   - 需要改成“block 内按类分层随机抽 n 条”，而不是按流顺序取前 n。

4. **N_τ 仍不可用**：
   - 多数 block n=0 已 ≥0.5，N_τ 中位数=0；
   - Periodic 有 4–9 个 censored block；
   - 需要更难的 threshold（0.8）或更难数据集（CIC）。

## 5. 结论（暂定）

- Periodic 在 10 天粒度下仍是三种 policy 中最低；
- 但 mapping-aware 的当前实现不是强攻击者，结果不能用于否定/确认“状态分组可消除 Periodic 优势”；
- 下一步必须先修：
  1. 标签预算改为 block 内分层随机抽样；
  2. expert 用全部历史（不 cap）或参数共享；
  3. state 选择用更多标签/更好的评分；
  4. 多 phase/seed。

## 6. 下一步

1. 修 prefix 偏差：分层随机 n 标签；
2. 修 expert：全部历史 + 状态特征/领域自适应；
3. 重跑 Periodic 的 unaware/schedule/state-inferred；
4. 再加 multi-phase/seed；
5. 最后扩 CIC/RF/MLP。
