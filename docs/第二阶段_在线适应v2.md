# 在线适应 v2：分层标签、共享状态模型、位置似然

## 1. 修复内容

1. **分层校准标签 + 时间因果盲测**
   - 每个 block 前 50% 为 calibration pool，后 50% 为 blind；
   - n 条标签在 pool 内按类分层随机抽取；
   - blind 固定，不随 n 改变。

2. **共享状态条件模型**
   - 历史特征追加 mapping state one-hot；
   - 所有状态共享一个模型，不再每个 state 单独 expert；
   - schedule-known 用真实 state；state-inferred 用推断 state。

3. **位置似然 state inference**
   - 从 trace 提取每条 flow 的 trigger 位置；
   - 对每个候选 state 计算观测位置的似然（按类先验加权）；
   - 选似然最大的 state。

## 2. 结果（Periodic，10 天/block，16 blocks，UNSW）

| attacker | method | n=0 | n=64 | n=256 | n=1024 |
| --- | --- | ---: | ---: | ---: | ---: |
| unaware | permutation | 0.673 | 0.651 | 0.651 | 0.651 |
| unaware | probe | 0.673 | 0.526 | 0.527 | 0.527 |
| unaware | finetune | 0.673 | 0.671 | 0.661 | 0.674 |
| schedule-known | permutation | 0.648 | 0.599 | 0.599 | 0.599 |
| schedule-known | probe | 0.648 | 0.507 | 0.510 | 0.511 |
| schedule-known | finetune | 0.648 | 0.634 | 0.647 | 0.655 |
| state-inferred | permutation | 0.642 | 0.588 | 0.558 | 0.588 |
| state-inferred | probe | 0.642 | 0.497 | 0.498 | 0.498 |
| state-inferred | finetune | 0.642 | 0.662 | 0.647 | 0.641 |

Nτ censored：unaware 3–4、schedule-known 4–5、state-inferred 5–6。

## 3. 观察

1. **Mapping-aware 仍没有超过 unaware**：
   - unaware permutation 0.651；
   - schedule-known 0.599；
   - state-inferred 0.588；
   - 真实 state 甚至略差，说明 state one-hot 让模型过拟合/分摊数据。

2. **Probe 在 n=64 明显伤性能**：
   - unaware 0.673→0.526；
   - 少量标签从头训练不稳定；
   - fine-tune 基本保持 0.65–0.67，是更稳的更新方式。

3. **n=1024 没有带来提升**：
   - 说明瓶颈不是标签数量，而是模型/特征/状态条件方式。

4. **State inference 可用但不够强**：
   - 位置似然能推断 state，但没有提高最终 BA；
   - 可能因为位置边际在 mapping 置换下不变，只有类先验提供弱信号。

## 4. 结论

- 在当前实现下，**mapping-aware 不能消除 Periodic 的成本**；
- 但也不能说“Periodic 优势真实”，因为：
  * state-conditioned 模型不是完整 canonicalization；
  * 历史 cap 5000；
  * 只有 Periodic、单 phase、SGD；
  * probe 的不稳定拖累了 n>0。

## 5. 限制

- 只跑 Periodic；
- 没有 Fixed/Per_flow 的 v2 对照；
- 没有 T_recovery（v2 未实现）；
- 没有多 phase/seed；
- 没有 CIC/RF/MLP；
- state inference 只用了位置似然，未用流量特征。

## 6. 下一步

1. 跑 v2 的 Fixed / Per_flow，同一协议；
2. 加 T_recovery；
3. 多 phase/seed；
4. 真正 canonicalization：按 state 逆变换 trigger code/position，而不是 one-hot；
5. 再扩 CIC/RF/MLP。
