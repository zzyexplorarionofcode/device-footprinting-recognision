# 当前映射标签校准：需要多少标签才能恢复？

## 1. 协议

- Arm A（placebo code + 类位置 + next mapping rotation）；
- 训练：old mapping；
- test days 分成**不相交**的 calibration pool 与 eval set；
- 从 calibration pool 抽 n 个带标签当前状态样本；
- 在 calibration 上估计 `pred→true` 的 Hungarian 置换；
- 应用到 eval predictions；test labels 不参与置换。

## 3. 为什么？与 position-only 的对照

Position-only 分类器：

- unaligned 0.000；
- validation-aligned 1.000（K=1）；
- 说明位置→类别信息仍在，且可由少量标签重新对齐。

Traffic classifier：

- 校准置换是一个 4-cycle（`3→0,0→1,1→2,2→3`）；
- calibration diagonal 与 eval diagonal 都不支持该置换；
- 置换来自 calibration 的偶然混淆，不能迁移到 eval days。

结论：

> Rotation 确实保留了位置信息（position-only 可完美对齐），但 traffic classifier 的失败不只是标签置换；它同时破坏了可迁移的表示。当前映射标签不足以恢复 traffic BA。

这修正了“rotation 只是暂时标签错位，少量标签即可恢复”的过度乐观解释。

## 4. 限制

- 只做了 UNSW、Arm A、LR；
- calibration/eval 按天不相交，存在时间分布差异；
- n 抽样未按类分层（小 n 时类别覆盖不稳定）；
- 没有 fine-tune/linear probe 方案；只做了置换估计；
- 没有 D/real 或 CIC。

## 5. 下一步

1. 用**随机 flow split**（同一天）重复校准曲线，区分“时间分布差异”与“表示不可恢复”；
2. 加 fine-tune/linear probe：用 n 个当前标签更新分类器，而不只是估置换；
3. CIC 与 D/real 复现；
4. 若 flat 仍成立，则 rotation 的收益不是“标签错位”，而是“表示破坏”，需要重新表述机制。
