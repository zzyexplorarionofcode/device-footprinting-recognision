# 评估协议（可复现）

本文件固定所有影响 BA 数值的处理与统计选择。新增实验必须复用这里的定义，否则结果不可比。

## 1. 数据集版本

| 简称 | 文件 | 类别 | 分组 |
| --- | --- | ---: | --- |
| CIC-9 | `data/processed/cic_v2/flows_cic_active_9class.npz` | 9（去掉只有 2 天的 LG） | 日期 |
| UNSW-8 | `data/processed/unsw_main8_v1/flows_unsw_8class.npz` | 8 | 日期 |
| UNSW18-9 | `data/processed/unsw2018_v1/flows_unsw2018_9class.npz` | 9（≥16 事件子集） | 日期 |
| Deakin-10 | `data/processed/deakin_v1/flows_deakin_10class.npz`（60 天）/ `..._full.npz`（119 天） | 10 | 日期 |

- 类别顺序以 `device_names` 为准，和 `configs/methods/fade_*.json` 的 `dataset.devices` 必须逐位一致。
- 类别筛选规则：只保留在至少 2 个日期出现、且流数 ≥50 的设备；CIC 去掉仅 2 天的 LG；UNSW18 只保留 ≥16 事件流；Deakin 选 92~116 天覆盖的 10 个设备名（多个 MAC 合并到同一设备名）。

## 2. 流表示

- 流定义：双向 5 元组（协议 + 排序后的 IP/端口），同一 `(device, flow_key)` 不跨天合并。
- 事件：`lengths`（Ethernet 帧长）、`gaps`（秒）、`directions`（±1）、`mask`（前缀有效位）。
- 观测窗口：前 **32** 个事件；`min_packets = 4`，至少 1 个上行事件。
- 方向：相对设备 MAC/IP；`pcap.parse_packet` 的 MAC 规则用于 CIC/UNSW；Deakin 用 SLL 源 MAC + 设备 IP。
- 帧长裁剪：>1514 统一裁到 1514（Mon/Deakin 的 SLL 帧尤其需要）。
- 分组：`groups = UTC 日期`；同一天的流不跨 train/test。

### 2.1 32 事件窗口的精确语义

1. 预处理先把原始流截成前 **32 个真实事件**，形成 `[N,32]` 的干净输入。
2. 防御在这 32 个事件中插入 5 个 dummy（2 trigger + 3 weakener），得到完整事件序列。
3. 攻击者看到的仍是该序列的**前 32 个事件**（post-insertion prefix），不是 37 个。
4. 因此最多 5 个真实事件会被挤出窗口；`displaced_real_packets` 统计的正是这种观测位移，不是网络丢包。
5. `require_all_dummies_in_window=false`：dummy 可能落在窗口外，`retained_dummy_count` 记录实际进入前 32 的 dummy 数；报告时必须区分 emitted 与 retained。

### 2.2 预算口径

- **630 B 是 L2 帧长/特征层字节**：`real_added_bytes`（真实包 padding）+ `dummy_bytes`（dummy 帧长），不含 Ethernet 前导码、FCS、IFG。按 5 个 dummy 估算，线缆上还要加约 5×24 B 的帧开销；论文若写 wire overhead 必须单独换算。
- **1.5 s 是新增时延预算**：各 dummy/真实事件的 gap 偏移之和，不是整条流持续时间，也不是端到端时延上界。
- 分账：weakener 347 B / 1.05 s / 3 个，trigger 283 B / 0.45 s / 2 个，合计 630 B / 1.5 s / 5 个；硬上限允许 6 个 dummy。


## 3. 预处理特例

- **CIC**：仅保留 TLS 候选流（443 + TLS record 头），`max_packets=32`。
- **UNSW-8**：混合流量，TLS 不强制；`min_packets=4`。
- **UNSW18-9**：PCAPNG 自动识别；保留 ≥16 事件流，去掉 Withings Baby Monitor（21 条）。
- **Deakin**：Linux cooked capture（link type 113）；SLL 头 16 B，VLAN 0x8100/0x88A8；源 MAC 为设备时方向 +1，目的 IP 命中设备 IP 时方向 −1；每类每天最多 300 条。

## 4. 数据划分

- **capture-disjoint split**：`split_by_capture(labels, groups, train_ratio=0.75, seed=42)`，按类分配完整日期；每类至少 1 个训练日 + 1 个测试日。
- **按天 K 折**（搜索/机制实验）：`assign_dates` 做多标签分层，每折整天验证，其余天训练；每类验证样本 ≥200（可配置）。
- **held-out A**：runner 的 `test` 划分；**held-out B**：A 中落在最后 20% 日期的子集（CIC/UNSW18 只有 1 天，仅参考）。
- 不把同一日期拆到两侧；不使用未来数据（没有未来数据）。

### 4.1 held-out 的措辞

- A 是 **capture-disjoint held-out evaluation**，不是盲测：它已被多轮查看，并影响过后续实验方向。
- B 只有 1 天，不能承担独立确认集。
- frozen candidate 的三折是 **同一日期池的重新划分**，不是未参与候选选择的外部确认集。
- 论文中禁止使用 untouched blind test / fully unseen confirmatory test；只能写 capture-disjoint / held-out evaluation，并注明复用。

## 5. 长度直方图攻击者

- 输入：每条流在观测窗口内的**有效事件**长度；默认包含真实包与 dummy（攻击者可见）。
- 直方图：`np.linspace(0, 1514, bins+1)`，**线性等宽**；计数除以该流事件数（归一化）。
- 默认 `bins = 16`；敏感性实验用 8/16/32/64。
- 分类器：
  - LR：`LogisticRegression(max_iter=500)`，标准化；
  - RF：`RandomForestClassifier(n_estimators=200, n_jobs=4, random_state=0)`；
  - MLP：`MLPClassifier(hidden_layer_sizes=(128,), max_iter=200, random_state=0)`，标准化。
- 三种定义：
  - **C→C**：干净 train → 干净 test；
  - **C→D**：干净 train → 防御后 test（mapping=next）；
  - **D→D**：防御后 train（mapping=old）→ 防御后 test（mapping=next）。
- 迁移损失 `loss = C→C − C→D`；适应恢复 `recovery = D→D − C→D`；适应增益 `adaptation = D→D − C→C`。

### 5.1 feature_source 必须显式

- `merged`：窗口内真实包 + dummy 的长度直方图；这是攻击者实际可见的输入。
- `real_only`：只取 `role == "real"` 的事件；这是 oracle 诊断，不是可部署攻击者。
- `C→D`/`D→D` 的数字必须带 `feature_source`；real-only 与 merged 不能混在同一列。
- 每个结果必须带 `run_id`，至少包含：`dataset_version / split_id / sample_protocol / feature_source / binning / classifier / regime`。

### 5.1b 机制分解

- 固定链式顺序：`CC → CD_complete → CD_visible → CD_merged`；三个差值（representation / displacement / dummy_mixing）**是路径依赖的，不可交换顺序，也不当作独立因果效应**。
- `CD_complete` 取防御后完整事件序列里的全部真实包（不做 32 窗口截断）；`CD_visible` 只取 `in_observation_window` 的真实包；`CD_merged` 取窗口内全部事件。
- `CD_complete` 与 clean 的差异只能来自防御对真实包本身的改动（padding/jitter）；Method33 的弱化层有 `padding_probability=0.58`，因此 representation 不必为 0。`padding_probability=0` 时必须严格为 0（控制实验）。
- 所有四个视图必须使用同一批 train/test 索引、同一分类器和同一预测协议；bootstrap 按测试日期配对重采样。

### 5.2 搜索目标

- 当前搜索目标为 `min_theta max(BA_clean^LR, BA_retrained^LR)`，只使用 LR。
- 论文表述必须是 **worst-case over clean/retrained LR**，不能写 worst-case over all attackers。
- RF/MLP 是事后复核，不是搜索目标；若要 worst-case over models，需要独立搜索。

## 6. 统计

- 样本：默认 train/test 各 8000（按类比例），或 P1-A 每类 300、P1-B 每类每 bin 300。
- 配对 bootstrap：以**测试日期**为重采样单位（cluster bootstrap），500 次；同一次重采样同时计算 C→C/C→D/D→D，再取 loss/recovery/adaptation，得到配对 CI。
- 报告：point estimate + 95% percentile CI；不把独立 BA 的 CI 当作差值 CI。
- 逐类：`recall_score(labels=all classes, average=None)`；混淆矩阵按真实类归一化。
- **dummy-only 报告要求**：必须同时给出每个类的测试支持数（support）、逐类 Recall、`recall_sum`、`ba_from_recall = recall_sum / classes_present` 和 `accuracy`；BA 与 `ba_from_recall` 必须一致。不得只列前 5 类后写"其余全为 0"；描述只能是"少数类主导"或"集中在 k 个类"，并注明 k 与各类 support。dummy-only 的 BA 不能单独作为"dummy 可指纹化"的证据。

## 7. 分层与匹配

- **P1-A 每类流数匹配**：每类取相同 n（≤300），train/test 独立抽样。
- **P1-B 事件数匹配**：防御前 `mask.sum` 分箱（默认 `4,8,12,16,20,24,32,33`）；每个 bin 内每类取相同 n（≤100–300）；样本不足的类在该 bin 中丢弃并记录。
- **分层 BA**：按事件数区间分别训练/测试（每类 cap 300），报告该层可用类集；共同类别分析时取各层类集交集。

## 8. 固定超参与随机性

- 所有实验 `seed=20261030`；bootstrap 的 RNG 由 seed+名称派生；FADE 的 `apply_method33` seed=731800。
- 分类器超参固定，不做逐数据集调参。
- 每次运行保存 JSON，包含样本数、类集、CI、耗时。

### 8.1 分块与逐流 RNG（已修复）

- `apply_method33` 的逐流随机性现在由 `SeedSequence([seed, flow_token])` 派生；`flow_token` 是**流内容指纹**（前 20 个事件，不含标签、mapping、批内下标）。
- 因此 chunk、重排、并行子批都会得到完全相同的 dummy 计划；`tests/test_method33_invariance.py` 覆盖 chunk/order/parallel/重复内容四种情况。
- 指纹只覆盖前 20 个事件，保留“20 号之后的 future suffix 不改变已发出前缀”的性质；当前配置最大 trigger position = 16。
- 历史 `hist_source3` 的 chunked 数字由旧 RNG 生成，**不得与 v2 结果混用**；v2 结果均来自 `v2_*` 文件。
- 若未来允许两条内容完全相同的流需要不同随机流，必须在调用前加入稳定的 dataset-level 标识；当前实现会让它们共享 token。
- **设计含义**：相同前 20 个事件的流共享同一弱化 dummy 计划。这是保留 future-suffix 性质的代价，不是安全随机性；攻击者若知道流内容可以重放该计划。因此内容指纹只保证实验可复现，不构成对攻击者的不可预测性；动态防御必须额外引入秘密状态与策略选择机制。

## 10. 已知限制

- CIC/UNSW18 的 held-out 日数少（6/5 天），CI 较宽。
- Deakin 为 60 天 pilot 或 119 天全量，二者需在结果中注明。
- P1-B 在短流/稀有类上可能无法做到严格逐类匹配；此时报告分层 BA 和可用类集。
- 所有数据已被多轮查看，属于机制分析而非盲测。
- dummy-only 的宏平均 BA 会被极少数高 Recall 类主导（例如 Deakin 的 Echo Show 8 = 1.0、TOPERSUN = 0.119，BA = 1.119/10）。因此必须同时报告 support、recall_sum 和 accuracy，不能把 BA 当作广泛可识别性。
